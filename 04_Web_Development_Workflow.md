# Web Development Project Workflow

## Default Workflow

Unless a project specifies a different process, use this workflow:

1.  Requirement received
2.  Requirement clarified
3.  Requirement documented
4.  Scope confirmed
5.  Development tasks created
6.  Dependencies identified
7.  Development begins
8.  Developer testing
9.  Staging deployment
10. QA / internal testing
11. UAT
12. Bug fixing
13. UAT retesting
14. Stakeholder acceptance
15. Production deployment
16. Post-deployment verification
17. Documentation
18. Project closure

## Requirement to Task Flow

Requirement → Clarification → Acceptance Criteria → Development Task →
Dependency Review → Implementation → Testing → UAT → Acceptance →
Deployment

## Handling Ambiguous Requirements

If a requirement contains phrases such as:

-   "make it better"
-   "add a report"
-   "allow users to manage"
-   "make it automatic"
-   "add notification"

Do not immediately create development tasks.

First identify what needs clarification.

Example questions:

-   Who can use the feature?
-   What information should be displayed?
-   What actions are allowed?
-   What happens in exceptional cases?
-   What is the expected output?
-   What conditions trigger the behavior?
-   What defines successful completion?

## Handling Scope Changes

When a new request appears:

1.  Compare it with approved scope.
2.  Determine whether it is already covered.
3.  If not covered, classify it as a possible change request.
4.  Identify impact on development, testing, timeline, and dependencies.
5.  Obtain the appropriate decision or approval.

## Definition of Done

A feature should not automatically be considered complete merely because
coding is finished.

Possible completion conditions:

-   Requirement implemented
-   Developer testing completed
-   Required bugs fixed
-   Staging verification completed
-   UAT completed
-   Required approval received
-   Documentation completed
-   Production deployment completed when applicable

The actual Definition of Done should follow the project's agreed
process.
